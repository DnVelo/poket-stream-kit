**「反応が無い」を証拠として扱う前に、その計測が生きていたことを別の入力で示すこと。**

**Why:** 2026-08-30 の入力調査で、`null` を2回続けて誤って結論にした。

1. 実機プローブを回して「押しても何も記録されない＝機器が信号を出していない」と報告した。
   ⚠ 実際は**プローブが2分で自動終了する作り**で、押していただく前に終わっていた。
2. 生イベントの記録を仕掛けて「全11台が0バイト」と報告した。
   ⚠ 実際は ssh を抜けた時点で `cat` が死んでいた（`setsid` を付けていなかった）。

⭐ 対照（確実に信号が出る操作を1つ）を混ぜた3回目で初めて、
   「対照だけ記録され、目的の操作は本当に何も出していない」が確定した。
⚠ どちらの誤報も**相手に押し直しを頼む往復**を増やした。ゼロは情報量が最も少ない観測なので、
   ⭐ **ゼロを主張するときこそ、装置が動いていた証拠を同じ記録の中に持たせる。**

**How to apply:**
- ⭐ 計測を仕掛けたら、**別接続から生存を確認**してから依頼する（`ps` で本数を見る）。
- ⭐ 依頼は「①確実に出る操作 → ②調べたい操作」の順にする。①が記録に無ければ計測側の失敗。
- ⚠ 背景実行は `setsid` ＋ ログへリダイレクト。⚠ 自動終了する道具は上限に達していないか確認する。
- ⚠ `/tmp` は tmpfs のことがある＝**再起動で道具ごと消える**（実際に消えた）。
