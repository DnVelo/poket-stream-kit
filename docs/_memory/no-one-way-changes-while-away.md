ユーザーが不在になる／席を離れると言った直後に、**戻せると確かめていない片道の変更**を
実行しないこと。特に起動順・ファームウェア・遠隔接続の経路など、
**失敗すると自分では戻せなくなる**類の変更。

**Why:** 2026-08-26 22:58 にユーザーが「夕方まで仕事で離れないといけない」と言い、
その **5 分後の 23:03** に私が `rpi-eeprom-config --apply` で起動順を USB 優先へ変えた。
翌日戻そうとして「USB のカーネルを退避すれば SD へ落ちるはず」と推測に賭けたが落ちず、
⚠ **ユーザーが帰宅して USB を物理的に抜くまで復旧不能**になった。
⚠ 当時は「帰り道の道具が無かった」という技術的な話として整理していたが、
記録を遡ると**より手前に、離れると聞いた直後に動いた**という判断の問題があった。

**How to apply:**
- 「離れる」「寝る」「出かける」と聞いたら、⭐ **その間にやる作業から退路のない変更を外す**。
- どうしても要るなら、⭐ **先に帰り道を実際に動かして確かめてから**行く。
- ⚠ **「こうすれば落ちるはず」という未確認の挙動に退路を賭けない。**
- ⭐ `cjboot`（[[os-round-trip-cjboot]]）は保険であって、この判断の代わりにはならない。
