## 1. 技術スタック

### 1.1 🟢 方針（2026-10-14 決定）
- 🟢 **Zig ＋ C++ の構成**（Gear-vk と同じ）。**極力 Zig で書き、C++ は避けられない所だけ**。
- 🟢 **目的は徹底した軽量化**。CPU とスケジューリングに余裕を作り、**ASIO のバッファを限界まで切り詰められる**ようにする。
- ❌ JUCE（叩き台）は不採用[^juce]。

### 1.2 🟡 各部をどう書くか（未決・候補）
| 部分 | 候補 | 備考 |
|---|---|---|
| ASIO | Zig から ASIO ドライバの COM インターフェースを直接呼ぶ／Gear-vk と同じ RtAudio（C++） | 🟡 x64 では素の COM の vtable 呼び出しなので Zig から呼べる見込み（🔴 未検証） |
| WASAPI | Zig から COM を直接呼ぶ／miniaudio（C・Zig から `@cImport` 可）[^gear-audio] | |
| VST3 ホスト | Steinberg の C 版ヘッダ（`vst3_c_api`）を Zig から使う／VST3 SDK（C++）の薄い層 | 🔴 C 版ヘッダで実用のホストが組めるかは未検証 |
| 画面 | Zig から Win32 を直接呼ぶ | プラグインのエディタも Win32 のウィンドウに載せる |

- ⚠ Gear-vk では miniaudio と RtAudio を**同時には開かない**設計だった[^gear-audio]。本ツールは**両方を同時に開くのが本題**なので、そこは新しく作る部分になる。
- ⚠ ASIO SDK のライセンス: Gear-vk の資料では「再配布不可」だが、**2.3.4（2025-10-15）から Steinberg 独自ライセンスと GPLv3 の選択制**になった[^asio-license]。

## 2. 信号経路

### 2.1 🟢 声（必須の部分）
```
ASIO in ─▶ [プラグインチェーン] ─┬─▶ ASIO out（ヘッドホン）
                                └─▶ クロック橋渡し ─▶ WASAPI 共有 / DirectSound out（VB-CABLE → OBS）
```
- 🟡 モニターを「処理後」にするか「処理前（プラグイン遅延ゼロ）」にするかの切り替えを持つか。

### 2.2 🟡 デスクトップ音・通話の取り込み（拾うことは決定・方法は未決）
| 方式 | 中身 |
|---|---|
| WASAPI ループバック | 既定の出力デバイスに流れている音を丸ごと拾う |
| アプリ単位のループバック | Windows のプロセス単位のキャプチャで、Discord などを個別に拾う（🔴 対応する Windows のバージョンは要確認） |
| 仮想ケーブル経由 | 各アプリの出力先を仮想ケーブルにして、本ツールがそれを入力として読む |

### 2.3 🟡 通話相手へ送る音
- 🟡 通話相手に処理後の声を送るなら、**通話アプリのマイク入力**になる出力がもう1本要る。
- 🟡 そこに通話の音そのものを混ぜない（相手に自分の声が返らない）構成にするか。

### 2.4 🟡 OBS へ送る形
- 🟡 全部を混ぜて VB-CABLE 1本で送るか、声・デスクトップ音・通話を別々に送るか。

## 3. デバイスとクロック

### 3.1 🟢 ASIO ドライバ = Creative ASIO（2026-10-14 決定）
- 🟢 **Play! 3 の Creative ASIO を使う**。ASIO4ALL は使わない。
- 🟢 X390 への導入と動作は**ユーザーが確認済み**（導入手順はユーザーが参照した note の記事[^creative-asio]）。
- 🔴 **完全な排他か、ASIO 以外の音も同時に Play! 3 から鳴らせるかは未検証**。ヘッドホンへ返す音の設計（`PSK_VISION §3.3`）がこれで変わる。
- 🟡 使えるバッファサイズとサンプルレートは未確認。

### 3.2 🟢 クロックの橋渡しは必須
- ASIO 側（Play! 3）と WASAPI 側（VB-CABLE）は**別のクロック**で動くので、ずれを吸収する仕組みが要る。
- 🟡 方式は未決。叩き台では「FIFO の水位を目標値に保つように、再生速度を PI 制御で微調整するリサンプラー」を実装し、シミュレーションで確かめた（`PSK_IMPLEMENTATION_STATUS §2`）。
